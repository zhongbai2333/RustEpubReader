# Application localization

All three clients use `core/src/i18n/en.json` and `zh_cn.json`. Edit those files together. Android copies them into generated assets before packaging; iOS copies them into the application bundle and generates localized `InfoPlist.strings` from the same permission key. There is no separate mobile translation table.

The persisted preference is `auto`, `zh_cn` or `en`. `auto` is retained as a preference rather than overwritten with the currently resolved language. Chinese system locales, including traditional Chinese regions, select the Chinese catalog. English and unsupported locales select English. Desktop checks changes while running; mobile clients refresh when the system configuration changes or the app returns to the foreground. Changing the interface language does not alter the book, reading position, notes, voice identifiers or font identifiers.

Templates accept indexed `{0}`, `{1}`, sequential legacy `{}`, named `{name}`, and literal braces `{{`/`}}`. Arguments are substituted once and are never parsed as templates. New keys should use indexed parameters so English may reorder arguments. Native numeric formatting uses the selected interface locale. Count labels use `.one` and `.other` variants, or a label/count form where a message contains multiple counters.

Stored application statuses are re-rendered when the interface language changes. Do not pass book content, titles, notes, downloaded prose or identifiers to the status translator. Protocol classifiers, linguistic correction dictionaries and font glyph samples intentionally remain in their original language. Each remaining source literal has an explicit reason in `scripts/i18n-literal-allowlist.json`; it is not a blanket exemption for a file.

Unknown keys fall back to a readable generic message instead of exposing the key. An invalid or incomplete catalog must be caught before packaging. English provides a runtime fallback when a selected entry is absent; this does not make incomplete source catalogs acceptable.

## Verification

- `python3 scripts/check-i18n.py`: duplicate/empty entries, key parity, placeholder parity, missing direct/conditional references, Chinese UI literals, and direct English UI labels/accessibility descriptions.
- `python3 scripts/test-i18n.py`: proves the gate rejects seven missing-key, placeholder, duplicate and hardcoded-label regressions in an isolated temporary checkout.
- `cargo test -p reader_core i18n --locked`: system preference persistence, formatter safety, plural counts and stored-status translation.
- `ios/scripts/check-i18n.sh`: checks the native Swift adapter with the actual shared catalog files.
- `./gradlew :app:testDebugUnitTest`: Android preference resolution and formatter safety.
- A Debug iOS installation launched with `--verify-i18n` writes `Library/Caches/i18n-verification.json`, without changing the user's language preference.

The source gate runs in CI, Android preBuild and the iOS translation packaging phase. Static checks do not prove every dynamic screen, native system sheet, remote server error or actual device locale transition. Check visible menus, settings, account/sync, statistics, narration, search and reset confirmation after UI changes. Platform-controlled permission sheets follow the platform's language rules.

## Language selection entry points

Android: Library menu → Language. Desktop: bottom Settings menu → Language. iOS: Library menu → Language. Reading settings reuse the same chooser on desktop and iOS. Each chooser displays the current preference and applies a selection immediately. Closing without a selection retains the current preference. Language choices live in a vertical list, with bounded scrolling when expanded in the future; there is no horizontal two-choice layout.

Desktop navigation keeps Library, Multi-platform sync and Return to reading in the upper group; Reading Stats and Settings remain at the bottom. The sidebar adapts its width to the translated labels, and the library search/sort row allocates space from the actual label width. A 600×400 layout regression covers both languages and guards against overlapping groups and elided labels.
